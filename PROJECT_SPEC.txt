PROJECT SPECIFICATION: Big Bertha Bringup
=========================================

OVERVIEW
--------
Big Bertha is a ROS 2 Jazzy quadruped (spider) robot with:
- 12 DOF (4 legs x 3 joints: hip, knee, ankle)
- PPO locomotion policy exported to ONNX, running from a C++ node
- Full autonomy stack: SLAM (slam_toolbox), AMCL localization, EKF state estimation, Nav2 path planning
- Gazebo Harmonic simulation with obstacle world
- Hardware target: Arduino UNO Q (arm64), 12x MG995 servos, PCA9685 PWM driver, YDLidar X2, MPU9250 IMU, STM32U585 co-processor

State: Simulation bringup is working. Hardware bringup is scaffolded with known issues.


PACKAGE ARCHITECTURE
--------------------

AUTONOMY STACK (DATA FLOW)
--------------------------
Gazebo (gz_ros2_control) -> /odom /imu /scan /joint_states -> ros_gz_bridge -> Policy Controller (ONNX PPO, 48-obs to 12-action) -> /position_controller/commands -> JointEffortPdController (Kp=20, Kd=2, sync PD) -> Gazebo effort interface -> EKF (robot_localization, 50 Hz, fuses odom+imu) -> odom->base_link tf -> SLAM (slam_toolbox) OR AMCL + map_server -> map->odom tf -> Nav2 (RegulatedPurePursuit, 0.12 m/s) -> /cmd_vel

Hardware path (future):
Policy Controller -> Hardware Bridge Node (TCP) -> Python Relay -> STM32U585 -> PCA9685 (I2C) -> 12x MG995 Servos
MPU9250 IMU (I2C) -> STM32U585 -> Python Relay (TCP) -> Hardware Bridge -> /imu


KEY DESIGN DECISIONS
--------------------
1. Joint ordering: All code uses Isaac articulation order (hips[0-3], knees[4-7], ankles[8-11]), matching trained policy
2. PD separation: PD moved from policy node to synchronous ros2_control plugin (JointEffortPdController) to avoid stale velocity feedback
3. Heading-hold + hip-bias steering: PI controller on heading error adds bias to hip joints to overcome weak yaw in DART/Gazebo
4. Lateral-hold: Closed-loop line tracking to reject systematic sideways drift from PhysX to DART transfer
5. Ground-filtered scan: /scan_filtered removes floor returns from body-tilting lidar, preventing ghost walls
6. Observation vector (48-d): root_lin_vel_b(3) + root_ang_vel_b(3) + projected_gravity_b(3) + commands(3) + joint_delta(12) + joint_vel(12) + prev_actions(12)
7. EWMA smoothing: Hardware bridge applies alpha=0.3 EWMA to smooth 50 Hz policy steps into servo trajectories
8. Rate limiter: Hardware bridge limits to 0.03 rad/step to prevent MG995 overspeed (max 6.54 rad/s)

Conversion Chain (radians to PWM):
Policy action (normalized, +/-1) -> action * action_scale (0.25) + default_joint_pos -> target position (radians) -> clamp to joint_limit (+/-3.14159) -> rate limiter (0.03 rad/step) -> EWMA smooth (alpha=0.3) -> (target - policy_center) * 57.3 * direction + offset + 90 -> servo angle (degrees) -> map(angle, 0, 180, pwm_min, pwm_max) -> PCA9685 PWM value (0-4095)
